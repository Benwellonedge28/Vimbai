# Code of conduct

## Our commitment

This project is a place to do careful work on financial software, where being wrong has consequences for real books and
real businesses. We commit to a working environment where anyone can report a problem, question a decision, or admit a
mistake without being treated badly for it.

## Expected behaviour

- Critique the change, not the person. "This breaks the reversal rule" is useful; "you don't understand accounting" is not.
- Say when you are unsure. A wrong assumption stated confidently costs more here than an open question.
- Assume the other person is trying to get it right, particularly when they are disagreeing with you.
- Report a defect you find in someone else's work as a finding, not a verdict.
- Respect that this is human work with limited hours.

## Unacceptable behaviour

Harassment, insults, discriminatory comments, sustained disruption, publishing someone's private information, and
deliberately withholding information that would prevent harm.

## Scope

Issues, pull requests, code review, commit messages, documentation and any space where someone is representing the
project.

## Reporting

Report a conduct problem privately to the repository owner, the same route as `SECURITY.md` describes for a
vulnerability. Reports are read by the owner, kept confidential, and answered within a reasonable time. The owner may
remove a comment, close a pull request, or bar a contributor, and will say which and why.

## Attribution

This policy is short on purpose. It is informed by the Contributor Covenant, narrowed to what applies to a small,
technically focused project rather than reproduced in full.
